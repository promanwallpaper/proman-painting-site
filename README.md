# ProMan Painting & Wallpaper — website

Static site for **ProMan Painting & Wallpaper** (Roman Ponomarenko, Lyman SC).
No frameworks, no build tools, no dependencies — plain HTML/CSS/JS generated by one
Python script. GitHub Pages serves the `docs/` folder directly.

Design reference: [foothillspainting.co](https://foothillspainting.co) — same structural
logic (dual CTA bar, bold colour-block hero, service cards, trust stats, FAQ, city pages),
rebuilt in ProMan's own brand: graphite `#2B2B2B` + orange `#E8792B` from the logo.

---

## How it works

```
build.py              ← ALL content and data lives here. This is the only file to edit.
assets/css/style.css  ← stylesheet
assets/js/main.js     ← mobile nav, dropdowns, before/after sliders
photos/               ← processed images (resized to 1600px, JPEG q72)
docs/                 ← GENERATED OUTPUT. Never edit by hand — it gets wiped on every build.
```

Rebuild after any change:

```bash
python3 build.py
```

That regenerates all 27 pages plus `sitemap.xml`, `robots.txt`, `llms.txt` and `CNAME`.

Preview locally:

```bash
python3 -m http.server 4173 -d docs
```

Then open <http://localhost:4173>.

### Claims that need paperwork first

`CLAIMS` at the top of `build.py` is deliberately all-off. Do **not** flip these until Roman
confirms — every one of them is a claim a customer could hold him to:

```python
CLAIMS = {
    "insured": False,     # general liability policy in hand?
    "licensed": False,    # SC licence?
    "years": None,        # years in business
    "warranty": None,     # e.g. "2-year workmanship warranty"
    "projects": None,     # completed projects
}
```

Flipping `insured` to `True` adds "Fully insured" to the promise list on every page that
shows it. Setting `years` swaps the "12 Upstate towns covered" stat tile for "X+ years in
business". Nothing appears anywhere until you set it.

### Reviews — do not write these

`REVIEWS` is an empty list on purpose. **Never invent testimonials.** Until real review text
is pasted in, `/reviews/` shows the verified ratings (5.0 Google / 4.9 Thumbtack) and links
out to both platforms so visitors read the real thing.

To add them, copy actual text from Google or Thumbtack:

```python
REVIEWS = [
    {"text": "…", "who": "Sarah M.", "source": "Google", "stars": 5},
]
```

## Deploying to GitHub Pages

The repo is already committed locally. It has **not** been pushed anywhere yet — creating the
GitHub account and repo has to be done by you, from the browser.

**1. Decide who owns it.** Roman's own GitHub account is the cleaner option — the site is his
asset and handover later is trivial. (The Viking site sits under `vikingdoorservice-ctrl`,
so a matching `promanpainting` account would be consistent.)

**2. Create an empty repo** at <https://github.com/new> — name it `proman-painting-site`,
public, and do **not** add a README, .gitignore or licence (this repo already has them).

**3. Push:**

```bash
cd "/Users/taras/Roma Ponomarenko/proman-site"
git remote add origin https://github.com/YOUR-ACCOUNT/proman-painting-site.git
git branch -M main
git push -u origin main
```

**4. Turn on Pages:** repo → *Settings* → *Pages* → Source: **Deploy from a branch** →
Branch: `main`, Folder: **`/docs`** → Save. First deploy takes a couple of minutes.

**5. Point the domain.** `docs/CNAME` is generated from `BIZ["domain"]`, so the repo already
tells GitHub which domain to expect. At the registrar, add:

| Type | Name | Value |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `YOUR-ACCOUNT.github.io` |

Then in *Settings → Pages*, enter the custom domain and tick **Enforce HTTPS** once the
certificate has been issued (can take up to 24h).

## Known gaps in the photography

Documented in full in `../ASSET-INVENTORY.md`. The short version:

- **No exterior photos exist at all.** `/exterior-painting/`, `/cabinet-painting/` and
  `/deck-and-fence-painting/` render a graphite panel instead of a photo, because showing a
  wallpaper picture on a cabinet-painting card would be misleading. Shoot these three and the
  cards fill themselves in — just add `"img"` to that service in `build.py`.
- **`1000015546.PNG` is not used and must not be.** The exterior before/after in the source
  folder is a render or AI recolour, not a real ProMan job.
- Several portfolio images are pre-made collages with a blue handwritten "Before/After"
  overlay. They work in the gallery grid but cannot drive the comparison slider. Clean
  originals would let all of them become sliders.
- The logo is a **square** stacked lockup, which is why the header has to be tall to keep it
  legible. A landscape version (icon left, wordmark right) would improve the header a lot.

## Images

Processed with `sips` (built into macOS) — resized to 1600px on the long edge, JPEG quality 72:

```bash
sips -Z 1600 -s format jpeg -s formatOptions 72 source.JPG --out photos/name.jpg
```

WebP would be roughly 30% smaller, but this machine's `sips` can read WebP and not write it.
If you install `cwebp` (`brew install webp`) it is worth redoing them.
